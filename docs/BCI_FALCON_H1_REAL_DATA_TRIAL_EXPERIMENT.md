# FALCON H1 overlap audit and bounded real-data trial experiment

This is a **custom, read-only research experiment**, not an unchanged FALCON benchmark run or a scientific acceptance decision. It investigates why the available public calibration/minival pairs cannot be used as independent file-level roles under the [ridge reference contract](BCI_FALCON_H1_RIDGE_REFERENCE.md). The pinned upstream revision is [`770c9b9`](https://github.com/snel-repo/falcon-challenge/tree/770c9b9597b8f58bf67b5a9ec6401ef705a2cb0f). Public assets came from mutable [DANDI 000954](https://dandiarchive.org/dandiset/000954), version `draft`; their UUIDs and local SHA-256 hashes, rather than the draft label, identify the analyzed bytes. The NWB dates below are **deidentified session labels**.

### What “prefix” means here

For **each** of S0, S1, and S2, minival timestamps start on the same regular 20 ms clock as calibration. The entire minival `OpenLoopKinematics`, `OpenLoopKinematicsVelocity`, `TrialNum`, and raw `eval_mask` arrays equal the first same-length calibration samples, including targets and mask values. All 176 unit IDs and each unit's raw spike timestamps through the minival last bin end also agree exactly; each minival spike list is a prefix of the matching calibration list. Binned spike counts consequently agree. This is observation overlap supported by time, trial and spike identity, not an inference from repeated zero values. S0 minival contains trial IDs 3 and 4, with 1,466 raw-mask true and 37 false samples and 71,718 spike timestamps; its final bin ends at 30.04 s. S1 contains trial IDs 1 and 2, with 1,629 true and 62 false samples and 81,852 spike timestamps; its final bin ends at 33.80 s. The local files match their advertised byte sizes and pinned SHA-256 values, so an incomplete local download does not explain this prefix relation.

The pinned [upstream README](https://github.com/snel-repo/falcon-challenge/blob/770c9b9597b8f58bf67b5a9ec6401ef705a2cb0f/README.md) describes calibration and minival as split held-in data. The inspected pinned preparation material did not establish why these DANDI assets share a prefix, or document a benchmark-permitted shared context for this pairing. DANDI exposes a mutable draft without a separate published release that resolves it. The production cause remains **unknown**; no upstream mistake is asserted. The unchanged file-level reference validator therefore still rejects these overlapping roles before fitting.

## Explicit custom route

The versioned `falcon-h1-ridge-custom-trials-spec-v1` uses complete in-file `TrialNum` segments and binds source SHA-256, original observation indices, documented role evidence, and fixed numerical settings. It was written to a private path and hashed **before** metrics were run; specification SHA-256: `cfd661147ee3746bebcb723e0c73ef364e187d472d652761c4a93d2d3b77bbd2`. There was no selection or hyperparameter search based on evaluation results.

S1 evaluation's last selected bin ends at 18.16 s; S1 calibration's first selected bin begins at 47.04 s. There are 1,444 unused source bins, or 28.88 s of unanalyzed time, between their analyzed windows. The custom validator proves the minival-to-calibration source-index mapping by exact raw arrays and spike-time prefix, rejects overlapping or adjacent selected windows, and requires whole trials. This one-bin minimum is dictated by the minival file's inclusive final bin boundary: immediately adjacent selections could count a boundary spike in both roles. The causal exponential kernel has 12 bins, lag history is zero, and filtering resets at the **training and evaluation** selection starts. Calibration normalization uses only selected raw counts and does not filter. Raw `eval_mask` remains unchanged. No selected evaluation observation can influence supervised fitting, five-fold alpha selection, normalization, or calibration; unselected preceding context is excluded from filter initialization.

The command is `dmri-studio bci ridge-h1-custom-trials --spec PRIVATE_SPEC.json --output PRIVATE_NEW_REPORT.json`. The Qt-free API is `run_h1_custom_trial_experiment(spec_path)`. The CLI refuses an existing output or source collision; the API returns a report without writing. Source files were read only and their SHA-256 values remained unchanged. The private report contains predictions, detailed exclusions, exact source identities and software versions. This route **changes source selection and filter resets** from the pinned file-level example; it is not an unchanged FALCON pipeline reproduction.

## Observed results and independent numerical check

The fixed 20 ms binning, 12-tap causal filter, first-80% fitting normalization, Ridge alpha grid `logspace(-5, 5, 20)`, five-fold model selection, and selected-recording calibration follow the pinned functions. Training had 3,917 union exclusions: 217 raw-mask false and 3,700 additional still-time samples; there were no nonfinite targets. The retained first-80% fitting split had 3,582 observations; its internal holdout had 886. Evaluation included 875 of 909 samples; 34 were excluded by the raw mask and none by nonfinite targets. Exclusion counts have explicit denominators and do not imply acquisition failure.

Selected alpha was `29763.51441631313`. Five-fold uniform-average R² was `0.00420`; internal holdout uniform-average R² was `0.11160` (variance-weighted `0.13513`). **Custom real-data evaluation** R² was `-0.17011` uniform-average and `0.02175` variance-weighted. Per output: tx `-0.10579`, ty `-0.99436`, tz `-0.09553`, rx `0.04724`, g1 `-0.06594`, g2 `0.02129`, g3 `0.00234`. The negative values are retained. These are a single short custom S1 trial's results, **not** the full FALCON evaluator or benchmark score.

The pinned upstream tarball was independently executed in an isolated Python 3.12.15 environment (NumPy 2.5.3, SciPy 1.18.1, scikit-learn 1.9.1, PyNWB 4.2.0, h5py 3.16.0). Its `load_nwb`, `prepare_train_test`, `fit_and_eval_decoder`, `SKLearnDecoder`, and `FalconEvaluator.compute_metrics_regression` operated on the **same selected real arrays**. Maximum absolute differences were 0 for all three roles' binned counts/targets, filtered training features, fitting and calibration normalization parameters, selected alpha, and internal holdout uniform-average R². Prediction difference was `1.52e-18`; single-session evaluator variance-weighted R² differed by `1.04e-16`. The `1e-12` tolerance reflects floating-point results in that pinned environment. This verifies shared numerical components, not benchmark data-role equivalence. No final evaluation submission occurred.

## Limits and verification

Only S0 and S1 were used for fitting/evaluation. The available selected durations are short, and there is one custom evaluated trial and task. The deidentified dates do not establish actual elapsed participant time; unit-ID or channel-count agreement does not establish neuron identity. The custom result does not resolve whether the original benchmark permits shared context. No quality score, scientific acceptance, GUI, adaptation, connectivity, anatomy, or live acquisition was added. The older reference route and overlap protection remain intact.

New tests cover exact whole-trial boundaries, role/source provenance, repeated/adjacent observations, raw spike and kinematic prefixes, filter-context isolation, evaluation-label isolation, CLI/API parity and source preservation. The focused BCI, CLI and scene suite passed **83 tests**. Ruff lint and formatting checks passed. A fresh-process import check found no new optional scientific, ML, Qt or VTK imports from the ridge core/CLI beyond the existing inspector baseline. The three experiment source SHA-256 hashes remained unchanged after the final CLI run. Private recordings, specification, upstream model and predictions stay outside the repository.
