# Guided Batch Processing

Open **Batch Processing** to process several acquisitions with one reviewed scientific workflow. The guided view has seven steps. **Advanced Settings** retains the workflow JSON, exact commands, resource budgets and journal controls used by existing studies.

1. **Select Data:** Choose a BIDS root, an explicit custom mapping, a CSV/TSV manifest, or a saved study. Discovery reads existing files and metadata; it starts no scientific processing. A saved study makes a new plan. A saved batch opens its previous approval, results and recovery state.
2. **Review Subjects:** Search, sort and filter discoveries. Select individual acquisitions by subject, session and acquisition identity. Discovery findings show missing or ambiguous inputs; they do not certify scientific eligibility. Selections stay intact when returning to this step. Changing the dataset replaces the selection with keys from the new study.
3. **Choose Workflow:** The guided presets currently cover conversion of validated DWI to MRtrix and calculation of FA/MD/AD/RD from an existing tensor image. A preset appears only when a selected acquisition advertises its required input role. Individual acquisitions lacking inputs remain visible and are reported as blocked by the plan. Conversion requires an explicit review of the source processing history; the application does not assert any prior corrections. Other supported batch workflows remain available by loading a saved workflow or opening Advanced Settings. The JSON editor and guided choices write to the same workflow definition.
4. **Configure:** Choose a **new** output folder. Existing batch outputs cannot be overwritten. New batches use saved MRtrix3, FSL and ANTs defaults from application Settings. Advanced resource limits govern concurrent subjects/processes, CPU threads and memory. The scientific planner verifies exact tools and inputs separately from displaying a saved path.
5. **Review Plan:** **Validate Processing Plan** performs a dry run. The review shows actual eligible, deferred and blocked stages, their findings, output and selected acquisition count. **Inspect Exact Commands and Provenance** opens the same plan in Advanced Settings. Execution requires checking approval of this exact plan. Editing subjects, workflow, output, resources or software invalidates that approval. Moving backward and forward without edits keeps the plan.
6. **Run & Monitor:** **Run Approved Batch** creates the approved batch and starts the existing runner. Status counts and per-stage details come from the journal. Pause stops scheduling new work; it does not promise immediate termination of an active command. Resume, selected cancellation, batch cancellation and retry retain the existing journal semantics. The log action shows the actual worker messages.
7. **Results & QC:** Inspect a stage's manifest and verified products, open a compatible product in the Viewer, inspect study or registration QC, record an explicit scientific review, and export reports. Execution completion is **not** scientific approval. Reopen a batch to inspect its historical paths and hashes or resume it under the engine's current identity checks. **New Batch With Current Software** starts a separate plan; it does not rewrite the earlier approved record.

The Batch page is created when first opened, then reused. Unchanged journals are not reparsed on every status timer callback, and the timer stops when the page is inactive. For command-line parity, `dmri-studio batch plan --acquisition-key SUBJECT/SESSION/ACQUISITION` may be repeated to plan an explicit discovered subset. The exported plan records those keys and binds them into its approval digest. Plans made before this option remain readable in their existing format.

For scientific restrictions and installation setup, see [limitations](limitations.md) and [dependency setup](dependency_setup.md).
