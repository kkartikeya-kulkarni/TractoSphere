# Experimental FALCON H1 ridge reference

This is a bounded, headless **research experiment**, not a benchmark submission, decoder recommendation, scientific acceptance decision, or clinical tool. The Qt-free API is `run_h1_ridge_experiment(spec_path)`; the CLI is `dmri-studio bci ridge-h1 --spec PRIVATE_SPEC.json --output PRIVATE_NEW_REPORT.json`. Install the optional `bci-reference` extra in an isolated environment. The ordinary TractoSphere import and GUI do not eagerly load scikit-learn, SciPy, NWB, Qt or VTK for this experiment. The report is created exclusively outside the repository; it contains source paths and predictions. The API does not write a file. This code never loads a model pickle. The independent upstream comparison used a pickle created inside a trusted private test process; passive inspection must never unpickle arbitrary models.

## Versioned experiment contract

Schema `falcon-h1-ridge-reference-spec-v1` requires exactly one recording in each `training`, `calibration` and `evaluation` role. This is the smallest reference path; it does **not** reproduce upstream `mode=all` across many training sessions. Each role binds an exact path and SHA-256, dataset version, asset UUID, participant pseudonym, deidentified session-day, recording set, benchmark partition, evidence for identity and partition, ordered unit IDs, and a documented `[start, stop)` observation span. Unknown partition or span evidence cannot be invented to run the experiment. The tool verifies hashes, selected NWB identity fields and internal role consistency; it records external evidence citations but does not verify their content over the network. Training must be `held_in_calib`; calibration must be held-in or held-out calibration; evaluation must be the corresponding held-in or held-out minival. Calibration and evaluation must name the same participant/session/set and partition side, with nonoverlapping observations. Matching IDs or channel counts across sessions do not establish biological neuron identity.

The fixed configuration is 20 ms bin-end windows, a normalized causal exponential filter `exp(-t/240 ms)` for `t=0,20,…,220 ms`, optional 0–59 history bins, first 80% training and remaining 20% internal holdout, H1 still threshold `abs(target) < 0.001` in **all seven outputs**, and `GridSearchCV(Ridge(), alpha=logspace(-5,5,20))` with five folds. The raw `eval_mask` is preserved. Fitting exclusions are raw mask false, still times and nonfinite targets; their counts may overlap, and history trims are reported separately. Nonfinite evaluation targets are additional local exclusions. This is a deliberate safety difference from upstream's NaN-only filtering, so such an input cannot claim exact evaluator conformance. Nonfinite neural features fail. A bin above 255 fails rather than reproducing upstream's silent `uint8` wrap. Each role is capped at five million count cells.

The upstream filter runs across `TrialNum` transitions without resetting. Fitting normalizes **filtered training features using the first 80%**, including rows later excluded by masks. Deployment instead normalizes filtered evaluation features with the **raw binned-count** mean/std of the matching calibration recording. Zero standard deviations become 1. Evaluation filtering and lag history start at zero for each file; lag order is current then previous. This normalization difference is retained as reference behavior. The NWB `starting_time` representation gives a regular 20 ms clock, so unrepresented acquisition gaps cannot be discovered. No trial-boundary reset is introduced.

Report schema `falcon-h1-ridge-reference-report-v1` records source hashes, software versions, exact configuration, selected alpha, fitting CV and internal holdout, exclusions, calibration parameters, intermediate array identities, every prediction and local evaluation metrics. Fitting uses scikit-learn's **uniform-average** multi-output R². Local single-recording evaluation reports per-output, uniform-average and variance-weighted R² separately. The pinned FALCON evaluator uses **variance-weighted R² per session**, then mean and standard deviation across sessions; a local result is not the official benchmark score. Fewer than two selected observations or a constant target feature give an explicit undefined metric.

## Independent pinned-upstream comparison

The pinned tarball was downloaded and executed in a private isolated Python 3.12.15 environment. Tarball SHA-256: `94650121d4f0b65aa78ed448e2c28b5e661ed4e19c4e22c8263af3a9b826297a`. Versions: NumPy 2.5.3, SciPy 1.18.1, scikit-learn 1.9.1, pandas 3.1.0, PyNWB 4.2.0, h5py 3.16.0, PyTorch 2.15.0 and Hydra 1.3.8. Reference functions ran from the unpacked pinned tarball, not copied into TractoSphere. File order was explicitly training, calibration, evaluation; upstream command-line `glob` order is otherwise unsorted. A synthetic 100-sample, two-unit, seven-target fixture with history 1 exercised upstream `bin_units`, `prepare_train_test`, `fit_and_eval_decoder`, `SKLearnDecoder` and `FalconEvaluator.compute_metrics_regression`.

On that compatible fixture, maximum absolute differences were **0** for binned counts, filtered features, normalization mean/std, selected training/holdout arrays, lag order, selected alpha and internal-holdout R². Predictions differed by at most `2.78e-17`; single-session evaluator variance-weighted R² matched exactly. The `1e-12` tolerance follows floating point behavior in this pinned Python/NumPy/SciPy/scikit-learn environment. Synthetic alpha was `69.51927961775606`; internal-holdout uniform-average R² was `-7.8441752317972995`, and local synthetic evaluation variance-weighted R² was `-2.1863902789318086`. These numbers establish implementation agreement, not model usefulness.

The real public S0 calibration, S1 calibration and S1 minival files were loaded read-only through both pinned upstream `load_nwb` and this implementation. Shapes were `10819×176`, `12233×176` and `1691×176`; binned counts, velocity targets and raw masks matched exactly. Filtered S0 calibration features also matched with maximum absolute difference 0. Source hashes remained unchanged. A full upstream `sklearn_sample.py` minival invocation was **not run**, because matching available calibration/minival assets overlap and violate the specified separation contract. No final-evaluation labels were used.

## Verification and limits

Synthetic tests cover causal filtering, lag order, pinned-upstream fixture values, training-only fitting parameters, evaluation-label isolation, calibration identity, partition/source conflicts, overlap, masks, nonfinite/constant targets, overflow, deterministic reruns, exclusive output, CLI/API parity and source preservation. The focused BCI/CLI/scene suite passed **76 tests** using the private reference environment. Ruff lint and formatting checks passed. A fresh-process import comparison showed this module and the BCI CLI add no eager scikit-learn, h5py, PyNWB, torch, Qt, VTK or SciPy imports beyond the existing inspector baseline. The [inspector](BCI_FALCON_H1_INSPECTOR.md) and [inventory](BCI_FALCON_H1_INVENTORY.md) retain their descriptive contracts. The private synthetic fixture, trusted fitted pickle, upstream source and path-bearing comparison JSON are not committed. Real decoder validation requires documented, nonoverlapping calibration/evaluation observations with matching session/set identity. This milestone adds no GUI, decoder adaptation, connectivity, anatomy or live acquisition.
